HTML 파일을 더블클릭하면 브라우저에서 바로 열립니다. 그런데 어떤 프로젝트는 "로컬 서버로 실행하세요"라고 안내합니다. 이 블로그도 그렇습니다. 파일을 그냥 열면 되는데 왜 굳이 서버가 필요할까요?

## 주소창을 먼저 보세요

파일을 더블클릭해서 열면 주소창이 이렇게 보입니다.

```text
file:///C:/Users/me/my-blog/index.html
```

로컬 서버로 열면 이렇게 바뀝니다.

```text
http://localhost:8000/index.html
```

화면은 똑같아 보여도 브라우저 입장에서는 완전히 다른 상황입니다.

| 구분 | `file://` | `http://localhost` |
| --- | --- | --- |
| 파일을 주는 쪽 | 운영체제(디스크에서 직접 읽음) | 내 컴퓨터에서 도는 웹 서버 |
| `fetch()`로 파일 읽기 | 대부분 막힘 | 가능 |
| ES 모듈(`type="module"`) | 막히는 경우가 많음 | 가능 |
| 실제 배포 환경과 비슷한가 | 아니오 | 예 |

## 왜 file://에서는 막힐까?

브라우저는 보안을 위해 **출처(origin)** 라는 개념으로 "어디서 온 페이지가 어떤 자료를 읽을 수 있는지"를 엄격하게 제한합니다.

`file://`로 연 페이지가 `fetch()`로 다른 파일을 자유롭게 읽을 수 있다면, 다운로드한 HTML 파일 하나가 내 컴퓨터의 다른 파일을 몰래 읽어 갈 수도 있겠죠. 그래서 브라우저는 `file://`에서의 요청을 대부분 막아 둡니다.

> 개발자 도구 콘솔에 `CORS policy` 나 `origin 'null'` 같은 오류가 보인다면, 거의 대부분 이 경우입니다.

이 블로그는 `posts/` 폴더의 마크다운 파일을 `fetch()`로 읽어 오기 때문에, 서버 없이 열면 글 목록이 나타나지 않습니다.

## 명령어 한 줄로 서버 띄우기

어렵게 들리지만, 정적 파일을 보여 주는 서버는 명령어 한 줄이면 됩니다. 프로젝트 폴더에서 터미널을 열고 아래 중 하나를 실행하세요.

**Python이 설치되어 있다면**

```bash
python -m http.server 8000
```

**Node.js가 설치되어 있다면**

```bash
npx serve .
```

그다음 브라우저에서 `http://localhost:8000` 을 엽니다. 서버를 끄려면 터미널에서 `Ctrl + C` 를 누르면 됩니다.

## 알아 두면 좋은 용어

- **localhost**: "바로 이 컴퓨터"를 가리키는 이름입니다. 숫자 주소로는 `127.0.0.1` 입니다.
- **포트(port)**: 한 컴퓨터 안에서 여러 프로그램을 구분하는 번호입니다. `8000`, `3000`, `5500` 등을 개발용으로 자주 씁니다.
- **정적 서버**: 파일을 있는 그대로 전달만 하는 서버입니다. 로그인이나 데이터베이스 같은 처리는 하지 않습니다.

## 자주 만나는 문제

1. **"Address already in use" 오류**
   - 같은 포트를 다른 프로그램이 쓰고 있다는 뜻입니다. `python -m http.server 8001` 처럼 번호를 바꿔 보세요.
2. **고쳤는데 화면이 그대로예요**
   - 브라우저 캐시 때문일 수 있습니다. `Ctrl + Shift + R` 로 강력 새로고침을 해 보세요.
3. **다른 폴더가 열려요**
   - 서버는 명령어를 실행한 폴더를 기준으로 파일을 보여 줍니다. 터미널이 프로젝트 폴더에 있는지 확인하세요.

## 정리

로컬 서버는 내 컴퓨터에 작은 웹 사이트를 잠깐 열어 두는 것입니다. `file://`로는 막히는 `fetch()`와 모듈이 제대로 동작하고, 실제로 배포했을 때와 거의 같은 환경에서 확인할 수 있습니다. 웹 개발을 시작했다면 **"파일 더블클릭" 대신 "서버 띄우기"** 를 습관으로 만들어 보세요.
