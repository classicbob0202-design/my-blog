코드를 고치다가 "아까 잘 되던 상태로 돌아가고 싶다"는 생각이 든 적이 있나요? 파일을 `최종.html`, `진짜최종.html`처럼 복사해 두는 대신, 개발자들은 **Git**이라는 도구로 변경 기록을 남깁니다. 오늘은 Git의 가장 기본 단위인 **커밋(commit)** 을 정리해 봅니다.

## 커밋은 게임의 세이브 포인트

커밋은 **프로젝트의 특정 순간을 찍어 둔 스냅숏**입니다. 게임에서 보스 방 앞에서 저장해 두는 것처럼, 의미 있는 작업을 마칠 때마다 커밋을 남겨 두면 언제든 그 시점으로 돌아가거나 무엇이 바뀌었는지 비교할 수 있습니다.

커밋 하나에는 다음 정보가 함께 저장됩니다.

- 바뀐 파일의 내용
- 누가, 언제 만들었는지
- 무엇을 왜 바꿨는지 적은 **커밋 메시지**

## 세 개의 공간

Git을 처음 배울 때 가장 헷갈리는 부분은 파일이 거쳐 가는 세 공간입니다.

| 공간 | 하는 일 | 비유 |
| --- | --- | --- |
| 작업 폴더 | 지금 편집하고 있는 파일 | 책상 위 |
| 스테이징 영역 | 다음 커밋에 넣을 변경을 골라 둔 곳 | 택배 상자 |
| 저장소 | 커밋이 쌓이는 기록 보관소 | 창고 |

파일을 고친 뒤 바로 저장소에 들어가는 게 아니라, **상자에 담고(add) → 상자를 봉해서 보관(commit)** 하는 두 단계를 거친다고 생각하면 쉽습니다.

## 기본 명령어 다섯 가지

```bash
git init                 # 현재 폴더를 Git 저장소로 만들기
git status               # 무엇이 바뀌었는지 확인하기
git add index.html       # 변경을 스테이징 영역에 담기
git commit -m "목록 페이지 제목 수정"   # 커밋 만들기
git log --oneline        # 지금까지의 커밋 기록 보기
```

처음에는 `git status`를 자주 입력하는 습관을 들이세요. 지금 어떤 파일이 어느 공간에 있는지 Git이 친절하게 알려 줍니다.

## 좋은 커밋 메시지 쓰기

커밋 메시지는 몇 달 뒤의 나 자신에게 남기는 메모입니다.

> 나쁜 예: "수정", "asdf", "이것저것"
>
> 좋은 예: "다크 모드에서 링크 색 대비 높이기"

몇 가지 요령을 기억해 두면 좋습니다.

1. **한 커밋에는 한 가지 일만** 담습니다. 버그 수정과 디자인 변경은 따로 커밋합니다.
2. 메시지는 **무엇을 했는지** 짧고 구체적으로 씁니다.
3. 작게, 자주 커밋합니다. 되돌리기도 리뷰하기도 쉬워집니다.

## 마치며

Git에는 브랜치, 병합, 원격 저장소 같은 기능이 더 있지만, 모든 것의 출발점은 결국 커밋입니다. 오늘 만든 작은 프로젝트 폴더에서 `git init`부터 입력해 보세요. 세이브 포인트가 하나씩 쌓이면 코드를 고치는 일이 훨씬 덜 무서워집니다.
