웹 접근성은 장애가 있는 사람을 포함해 **누구나** 웹 페이지를 이용할 수 있게 만드는 일입니다. 화면 읽기 프로그램을 쓰는 사람, 마우스 대신 키보드만 쓰는 사람, 햇빛 아래에서 휴대폰을 보는 사람 모두가 대상입니다.

거창해 보이지만, 기본 몇 가지만 지켜도 크게 달라집니다.

## 1. 알맞은 태그 쓰기

모든 것을 `<div>`로 만들지 말고, 뜻에 맞는 태그를 고릅니다.

- 클릭해서 동작하는 것은 `<button>`, 다른 페이지로 가는 것은 `<a>`를 씁니다.
- 페이지 구역은 `<header>`, `<nav>`, `<main>`, `<footer>`로 나눕니다.
- 제목은 `<h1>`부터 순서대로 씁니다. 글자 크기를 키우려고 제목 태그를 고르지 않습니다.

`<button>`은 키보드 포커스와 Enter·Space 키 동작을 기본으로 갖고 있습니다. `<div>`로 버튼을 흉내 내면 이것을 전부 직접 만들어야 합니다.

## 2. 이미지에 대체 텍스트 달기

화면 읽기 프로그램은 이미지 대신 `alt` 속성을 읽어 줍니다.

```html
<img src="chart.png" alt="10월 방문자 수가 9월보다 20% 늘어난 막대 그래프">
<img src="divider.png" alt="">
```

꾸미기용 이미지는 `alt=""`로 비워 두면 화면 읽기 프로그램이 건너뜁니다.

## 3. 키보드만으로 써 보기

마우스를 치우고 `Tab` 키만으로 페이지를 돌아다녀 보세요.

- 지금 어디에 포커스가 있는지 눈에 보이나요?
- 모든 링크와 버튼에 닿을 수 있나요?

CSS에서 `outline: none`으로 포커스 표시를 지웠다면 `:focus-visible`로 다른 표시를 꼭 넣어 줍니다.

## 4. 글자와 배경의 대비 지키기

연한 회색 글씨는 세련돼 보이지만 읽기 어렵습니다. WCAG 기준으로 본문은 대비 **4.5:1 이상**, 큰 글씨는 3:1 이상이어야 합니다.

| 조합 | 대비 | 본문에 쓸 수 있나 |
| :--- | :---: | :---: |
| 흰 배경 + `#1f2328` | 약 15.8:1 | 예 |
| 흰 배경 + `#59636e` | 약 6.1:1 | 예 |
| 흰 배경 + `#aaaaaa` | 약 2.3:1 | 아니요 |

## 5. 아이콘 버튼에 이름 붙이기

글자 없이 아이콘만 있는 버튼은 화면 읽기 프로그램에서 "버튼"이라고만 들립니다. `aria-label`로 이름을 붙여 줍니다. 켜고 끄는 버튼이라면 `aria-pressed`로 현재 상태도 알려 줍니다.

```html
<button type="button" aria-label="다크 모드" aria-pressed="false">🌓</button>
```

이 블로그의 다크 모드 버튼도 이렇게 만들었습니다.

## 마치며

> 접근성은 마지막에 덧붙이는 기능이 아니라 처음부터 함께 챙기는 품질입니다.
