웹 페이지를 만들다 보면 "왜 이 글자가 안 보이지?", "버튼을 눌렀는데 아무 일도 안 일어나네?" 같은 순간이 꼭 옵니다. 이럴 때 가장 먼저 열어 볼 곳이 바로 **브라우저 개발자 도구**(DevTools)입니다. 따로 설치할 필요도 없고, 크롬·엣지·파이어폭스 같은 브라우저에 이미 들어 있어요.

## 여는 방법

- 윈도우: `F12` 또는 `Ctrl + Shift + I`
- 맥: `Cmd + Option + I`
- 페이지에서 마우스 오른쪽 클릭 → **검사**

창이 열리면 위쪽에 여러 탭이 보입니다. 처음에는 다 알 필요 없고, 아래 네 가지만 기억하면 충분합니다.

## 1. Elements: 페이지의 뼈대 들여다보기

**Elements** 탭은 지금 화면에 그려진 HTML과 거기에 적용된 CSS를 보여 줍니다.

- 왼쪽 위 화살표 아이콘을 누른 뒤 페이지의 요소를 클릭하면, 그 요소의 HTML 위치로 바로 이동합니다.
- 오른쪽 **Styles** 영역에서 CSS 값을 직접 고쳐 볼 수 있어요. 색이나 여백을 바꾸면 화면에 즉시 반영됩니다.
- 줄이 그어진 CSS 속성은 다른 규칙에 밀려서 *적용되지 않은* 것입니다.

> 여기서 고친 내용은 새로고침하면 사라집니다. 마음에 드는 값을 찾았다면 원래 CSS 파일에 옮겨 적어야 해요.

## 2. Console: 에러 메시지 확인하기

**Console** 탭은 자바스크립트가 남긴 메시지를 보여 줍니다. 버튼이 동작하지 않을 때 빨간 에러가 찍혀 있는 경우가 많아요. 직접 코드를 입력해서 실행해 볼 수도 있습니다.

```js
console.log('여기까지 실행됐어요!');
document.title; // 현재 페이지 제목 확인
```

코드 중간에 `console.log()`를 넣어 두면 "어디까지 실행됐는지", "변수에 어떤 값이 들어 있는지"를 쉽게 확인할 수 있습니다. 가장 단순하지만 가장 많이 쓰는 디버깅 방법이에요.

## 3. Network: 파일이 제대로 왔는지 보기

**Network** 탭은 페이지가 서버에서 받아 온 모든 파일(HTML, CSS, 이미지, 데이터 등)을 목록으로 보여 줍니다. 탭을 연 상태로 새로고침해야 기록이 남아요.

| 상태 코드 | 뜻 |
| --- | --- |
| 200 | 정상적으로 받아 왔어요 |
| 304 | 바뀐 게 없어서 저장해 둔 것을 썼어요 |
| 404 | 그런 파일이 없어요(경로 오타를 의심!) |
| 500 | 서버 쪽에서 문제가 생겼어요 |

이미지가 안 보이거나 데이터가 안 불러와질 때는 여기서 **빨간색 줄**을 먼저 찾아보세요.

## 4. 기기 모드: 모바일 화면 미리 보기

개발자 도구 왼쪽 위의 휴대폰·태블릿 모양 아이콘(`Ctrl + Shift + M`)을 누르면 화면 폭을 바꿔 가며 볼 수 있습니다. 375px 같은 모바일 폭에서 글자가 넘치거나 가로 스크롤이 생기지 않는지 확인할 때 유용해요.

## 마무리

개발자 도구는 처음엔 복잡해 보이지만, 결국 "지금 브라우저 안에서 무슨 일이 일어나고 있는지" 보여 주는 창입니다. 문제가 생기면 다음 순서로 살펴보는 습관을 들여 보세요.

1. **Console**에 빨간 에러가 있는지
2. **Network**에서 파일이 404로 실패하지 않았는지
3. **Elements**에서 HTML과 CSS가 생각한 대로 적용됐는지

이 세 가지만 확인해도 대부분의 문제는 실마리를 찾을 수 있습니다.
