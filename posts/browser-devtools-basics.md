웹 페이지를 만들다 보면 "왜 이 글자가 안 보이지?", "버튼을 눌러도 왜 아무 일이 없지?" 같은 순간이 꼭 옵니다. 이럴 때 가장 먼저 열어 볼 곳이 **브라우저 개발자 도구**입니다. 따로 설치할 필요 없이 크롬, 엣지, 파이어폭스, 사파리에 모두 들어 있습니다.

## 여는 방법

| 방법 | Windows / Linux | macOS |
| --- | --- | --- |
| 단축키 | `F12` 또는 `Ctrl + Shift + I` | `Cmd + Option + I` |
| 요소 바로 검사 | `Ctrl + Shift + C` | `Cmd + Shift + C` |
| 마우스 | 페이지에서 우클릭 → **검사** | 페이지에서 우클릭 → **요소 검사** |

> 사파리는 먼저 설정 → 고급에서 "웹 개발자용 기능 보기"를 켜야 메뉴가 나타납니다.

탭이 많아서 처음엔 복잡해 보이지만, 아래 네 가지만 알아도 대부분의 문제를 스스로 찾을 수 있습니다.

## 1. Elements: 화면이 왜 이렇게 보이는지

**Elements**(파이어폭스는 *검사기*) 탭은 지금 페이지의 HTML 구조와 각 요소에 적용된 CSS를 보여 줍니다.

- 왼쪽에서 요소를 고르면 오른쪽에 그 요소의 스타일이 나옵니다.
- 줄이 그어진 CSS 속성은 **다른 규칙에 덮어써져서 적용되지 않은** 것입니다. "분명 색을 바꿨는데 안 바뀐다"면 여기부터 봅니다.
- 값을 클릭해 바로 고칠 수 있습니다. 새로고침하면 사라지니, 마음에 드는 값을 찾으면 코드에 옮겨 적으세요.

## 2. Console: 오류 메시지와 실험실

**Console** 탭에는 자바스크립트 오류가 빨간 글씨로 찍힙니다. 버튼이 동작하지 않을 때 이 탭을 열면 원인이 적혀 있는 경우가 많습니다.

```text
Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')
    at main.js:12
```

이 메시지는 "`main.js` 12번째 줄에서 찾으려던 요소가 없었다(`null`)"는 뜻입니다. 오른쪽의 파일 이름을 누르면 그 줄로 바로 이동합니다.

콘솔은 코드를 직접 입력해 보는 실험실이기도 합니다.

```js
document.title;                       // 현재 페이지 제목
document.querySelectorAll('a').length; // 링크 개수
console.log('여기까지 실행됨');        // 내 코드에 넣어 두면 실행 흐름 확인
```

## 3. Network: 파일을 제대로 받았는지

**Network** 탭은 페이지가 불러온 모든 파일(HTML, CSS, 이미지, `fetch` 요청 등)을 목록으로 보여 줍니다. 탭을 연 상태에서 새로고침해야 기록이 남습니다.

| 상태 코드 | 의미 |
| --- | --- |
| `200` | 정상적으로 받아 옴 |
| `304` | 바뀐 게 없어 캐시를 사용함 |
| `404` | 파일을 찾지 못함(경로나 파일명 오타 의심) |
| `500` | 서버 쪽 오류 |

이미지가 깨지거나 글이 안 불러와질 때 빨갛게 표시된 `404` 줄이 있는지 먼저 확인해 보세요. 대부분은 경로의 대소문자나 오타 문제입니다.

## 4. 기기 모드: 모바일에서는 어떻게 보일지

Elements 탭 왼쪽 위의 휴대폰·태블릿 모양 아이콘(크롬 기준 `Ctrl + Shift + M`)을 누르면 화면 폭을 바꿔 볼 수 있습니다. 375px 정도로 줄여서 다음을 확인해 보세요.

1. 가로 스크롤이 생기지 않는지
2. 글자가 너무 작거나 줄이 너무 길지 않은지
3. 버튼과 링크를 손가락으로 누르기 충분히 큰지

## 마치며

처음부터 모든 탭을 알 필요는 없습니다. 문제가 생기면 **"화면이 이상하면 Elements, 동작이 이상하면 Console, 파일이 안 오면 Network"** 순서로 열어 보는 습관만 들여도 디버깅 시간이 확 줄어듭니다. 오늘 아무 사이트에서나 `F12`를 눌러 한 번 둘러보는 것부터 시작해 보세요.
