## 사용자 요구사항
- 16×16 격자에 도트를 찍어 그림을 그린다.
- 완성하면 PNG로 저장할 수 있다.
- 색상 팔레트를 넣는다.

## 지켜야 할 조건 (CLAUDE.md에서)
- HTML, CSS, JavaScript만 사용. 외부 라이브러리는 최소화(CDN은 허용하지만 이 앱에는 필요 없을 것 — PNG는 `<canvas>`의 `toBlob`으로 만든다).
- `/apps/pixel-art/` 폴더 안에서 자체 완결. 블로그와 다른 앱의 파일을 수정하지 않는다(import하지 않고, 필요하면 값만 복사).
- 모바일에서도 사용 가능해야 한다 → 손가락으로 찍고 드래그해서 칠하기, 375px 폭에서 가로 스크롤 없음, 그리는 중 페이지가 스크롤되지 않게.
- 사이트는 GitHub Pages 하위 경로(`/my-blog/`)에서 서비스된다. 모든 경로는 상대 경로.
- 나중에 블로그 메인(`index.html`)의 웹앱 섹션에 카드로 들어간다.

## spec.md에 담을 내용
한국어로, 간결하지만 구현자가 추측할 필요 없을 만큼 구체적으로 쓴다.

1. **개요**
2. **기능 목록** — 최소한 다음을 정한다:
   - 그리기: 클릭/탭으로 한 칸 칠하기, 드래그로 이어 칠하기(빠르게 움직여도 칸이 비지 않게 — 선 보간), 지우개(투명), 전체 지우기(확인 방법 포함)
   - 팔레트: 기본 색 개수와 구체적인 색 목록(투명 포함 여부), 선택 색 표시, 사용자 색 고르기(`<input type="color">`) 여부
   - PNG 저장: 출력 크기(16×16 원본 그대로인지, 확대 배율 선택인지), 투명 배경 유지, 파일 이름, 모바일에서의 저장 동작
   - 편의 기능 중 이번에 넣을 것과 뺄 것을 판단: 되돌리기/다시하기, 스포이드, 채우기(flood fill), 격자선 표시 토글, 작업 자동 저장(`localStorage`)
   - 다크 모드(2048과 같은 방식, 테마 토글 포함)와 접근성(키보드로 칸 이동·칠하기 가능 여부, 버튼 44px)
3. **파일 구조** — 순수 로직(격자 데이터, 칠하기·채우기·되돌리기, PNG용 픽셀 배열 만들기)과 화면/입력 처리를 분리한다.
4. **핵심 로직 설계** — 격자 데이터 구조(색 표현 방식, 투명), 주요 함수 시그니처
5. **화면 구성** — 헤더, 캔버스/격자, 팔레트, 도구 버튼, 저장 버튼. 모바일/데스크톱 레이아웃. 격자를 DOM 칸 256개로 그릴지 `<canvas>` 하나로 그릴지 정하고 이유를 쓴다.
6. **디자인** — 블로그 토큰 복사, 앱 전용 변수(라이트/다크), 투명 칸 표시(체크무늬 등)
7. **블로그 임베드 계획** — 카드 제목·한 줄 설명, `preview.svg` 사양
8. **검증 체크리스트** — Review 단계용(PNG 결과 픽셀 값 확인 방법 포함)
9. **범위 밖**
10. **열린 질문** — 사용자가 정해야 할 것만, 각 질문에 권장 기본안을 붙인다.
