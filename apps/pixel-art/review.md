# Review — 픽셀 아트 에디터

> Review 단계 / 2026-10-22 / 브라우저: 내장 브라우저 새 탭, `http://localhost:8000/apps/pixel-art/`

## 요약

**통과(경미한 수정 2건 반영).** spec 8장 체크리스트를 순수 로직·그리기·팔레트/키보드·PNG·자동 저장·화면/테마·프로젝트 규칙 순서로 직접 확인했고, 기능 결함은 없었다. 다만 CLAUDE.md에 나중에 추가된 "사용법 안내 문구" 규칙에 비해 도구 단축키·되돌리기 단축키·PNG 저장 방법이 화면에 보이지 않아(단축키는 `title` 툴팁에만 있음) 안내 문단을 추가했고, 화면 배율(DPR)만 바뀌는 경우 캔버스 해상도를 다시 맞추도록 보강했다. PNG는 8.4 방법으로 실제 픽셀 값을 확인했고 모든 배율에서 기대값과 일치했다. 콘솔 오류는 없었다.

## 남은 문제 / 사용자 결정 필요

- **사용자 결정 필요 — 색 변수 "참조" 방식**: CLAUDE.md는 "style.css의 CSS 변수를 참조할 것"이라고 쓰고, spec(3장·6.1)은 "블로그 CSS를 import하지 않고 값만 복사"로 정했다. 현재는 spec대로 이름·값을 복사했다. 블로그 색이 바뀌면 앱도 손으로 맞춰야 한다. 블로그 `css/style.css`를 직접 `<link>`로 불러오게 바꿀지는 규칙 해석 문제라 고치지 않았다.
- 경미: 모바일(375px)에서 현재 색 칩이 되돌리기/다시하기 줄에 들어가지 못해 다음 줄 오른쪽에 붙는다. 기능·가독성에는 문제 없음.

## 확인하지 못한 것

- 실기기 터치(손가락 드래그 중 페이지 스크롤 차단, 길게 누르기 메뉴, iOS Safari/Android Chrome 저장 동작)
- 실제 파일 다운로드(클릭을 가로채 Blob만 확인)
- 스크린 리더 실제 낭독(`aria-live` 문구 갱신은 DOM으로만 확인)
- DPR만 바뀌는 상황에서의 실제 재렌더(코드로만 확인)
- OS 다크 설정 변경 추적(코드 확인, 저장값이 없을 때 OS 설정을 따르는 것만 확인)
- 내장 브라우저 창이 숨겨진 동안에는 `requestAnimationFrame`/`ResizeObserver`가 멈춰 렌더 확인에 지연이 있었음(앱 문제 아님)
