# 뽀모도로 타이머 — Review 결과

> 검토일 2026-10-30 · Build 담당과 다른 에이전트가 직접 실행·측정해 확인했다.

## 요약

**판정: 통과(수정 2건 반영).** spec 8.1의 Node 로직 테스트 20개를 직접 다시 짜서 돌렸고 모두 통과했다. 금지 패턴 grep, 대비 계산(라이트·다크 26개 조합), 브라우저 확인(첫 화면, 시작·일시정지, 새로고침 이어가기, 자리를 비운 사이 완료, 날짜 바뀜, 깨진 저장값, 단축키, 설정 오류, 테마, 375/768/1280 레이아웃, 탭 대상 44px, 콘솔)도 통과했다. Build가 "판단 필요"로 남긴 문제(진행 중에 현재 단계를 남은 시간보다 짧게 설정한 뒤 새로고침하면 세션이 버려짐)는 실제로 재현돼 버그로 보고 고쳤다. 같은 원인으로 진행 링이 틀리게 그려지던 문제도 함께 풀렸다. 추가로 설정 `summary`의 펼침 표시(▶)가 보이지 않던 문제를 고쳤다. 실제 소리, 알림 권한, 70초 백그라운드, 스크린 리더는 확인하지 못했다.

### Build가 spec과 다르게 한 점

| 항목 | 판단 | 메모 |
|---|---|---|
| `applySettings`: 휴식 단계의 `cycleCount`를 새 `longEvery`로 줄임 | 합리적 | 안 하면 `parseSession`의 `cycleCount ≤ longEvery` 검사에 걸려 새로고침 때 세션이 버려진다. 집중 단계 규칙(`longEvery - 1`)과도 어긋나지 않음 |

## 수정한 것

1. **`timer.js` — 진행 중 설정을 짧게 바꾼 뒤 새로고침하면 타이머가 처음부터 시작되던 버그**
   - 재현: 25분 집중 진행·일시정지 중 집중을 10분으로 저장 → 새로고침 → 남은 24분이 새 길이 10분보다 커서 `parseSession`이 세션을 버림. 사용자 입장에서는 진행 중이던 타이머가 사라지는 버그이고, spec의 "진행 중 바꾸면 다음 단계부터 적용"과도 어긋난다.
   - 같은 원인으로 진행 링도 틀렸다: `progress`가 새 설정 길이로 나눠 링이 가득 찬 채 있다가 갑자기 줄어들었다(길게 바꾸면 반대로 튐).
   - 고친 방법: 현재 단계 길이가 설정과 달라졌을 때만 상태에 선택 필드 `lengthMs`(그 단계의 원래 길이)를 붙인다.
     - `phaseLength(state, settings)` 추가: `state.lengthMs ?? durationMs(...)`.
     - `applySettings`: 손대지 않은 idle은 지금처럼 새 길이로 바꾸고, 그 밖에서 길이가 달라지면 `lengthMs`에 원래 길이를 기록(두 번 바꿔도 처음 길이 유지, 원래 길이로 되돌리면 제거).
     - `reset`은 `lengthMs`를 없애 새 설정 길이로 되돌린다. `skip`·`tick`이 만드는 새 단계에는 원래 붙지 않는다.
     - `progress`는 `phaseLength` 기준.
     - `toSession`은 `lengthMs`가 있을 때만 저장한다(평소 저장 형식은 그대로).
     - `parseSession`은 `lengthMs`가 있으면 그 단계 설정 범위 안의 1분 단위 정수인지 검사한 뒤, `remainingMs`·`endsAt` 범위를 그 길이로 검증한다. 잘못된 `lengthMs`는 세션 전체를 무효로 처리한다.
   - 확인: spec 8.1의 20개 테스트가 그대로 통과(기본 상태 모양은 바뀌지 않음). 추가 테스트 2묶음 통과. 브라우저에서도 일시정지 24:48 → 집중 10분 저장 → 새로고침 → 24:48 일시정지 유지, 링 위치 유지, R로 초기화하면 10:00을 확인했다.
2. **`style.css` — 설정 `<summary>`의 펼침 표시(▶)가 보이지 않던 문제**
   - `display: flex` 때문에 Chrome에서 `summary` 마커가 사라져 "설정"이 펼쳐지는 영역인지 알 수 없었다.
   - `display: list-item` + `line-height: var(--tap-size)`로 바꿔 ▶ 표시를 살리고 높이 44px를 유지했다(측정 44px).

## 남은 문제와 사용자 결정 필요 사항

- **사용자 결정 필요 없음.** 고친 두 건 모두 앱 폴더 안의 작은 수정이다.
- 참고: `pomodoro:session`에 선택 필드 `lengthMs`가 생겼다(진행 중 설정을 바꿨을 때만). spec 4.4 형식 설명에는 없는 필드라 spec을 고칠지 정해야 한다(Review는 spec을 수정하지 않음).
- 참고: 알림 영역 문장은 spec대로 `requestAnimationFrame`으로 넣어서, 숨겨진 탭에서는 그 탭이 다시 보일 때까지 늦게 들어간다(Build 메모와 같은 현상). 앞 탭에서는 바로 들어간다. 다른 탭을 보고 있을 때는 읽어 줄 필요가 크지 않아 그대로 두었다.

## 확인하지 못한 것

- 실제 비프 소리(소리 출력 확인 수단 없음). 코드는 spec 사양(880Hz sine, 0.15초 × 3, 0.25초 간격, 감쇠)과 일치.
- 브라우저 알림 권한 창과 거부 흐름(지침상 권한 창을 띄우지 않음). 코드만 확인.
- 다른 탭으로 70초 전환하는 백그라운드 테스트(8.3-4).
- 실제 Ctrl+R 입력(코드상 Ctrl 조합은 무시).
- 스크린 리더로 실제 읽힘. `aria-live` 영역의 `textContent` 변화만 확인.
- `localStorage` 자체가 예외를 던지는 환경(시크릿 차단 등)은 브라우저에서 재현하지 못했다. 모든 접근이 `try/catch` 안에 있는 것과 깨진 값에서 기본값으로 동작하는 것만 확인.
