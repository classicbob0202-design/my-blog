## 사용자 요구사항
- 뽀모도로 타이머: 집중(기본 25분) / 짧은 휴식(기본 5분)을 번갈아 진행. 시작·일시정지·초기화(또는 건너뛰기).
- 오늘 완료한 집중 횟수를 저장해 보여 주기(날짜가 바뀌면 0부터).
- 사용법 안내 문구를 화면에 넣기(조작법, 단축키, 저장 방식).
- 아래는 권장안을 붙여 "열린 질문"으로 제안하라:
  - 4번 집중 후 긴 휴식(15분)을 둘지
  - 시간 설정(분) 변경 기능을 넣을지, 넣는다면 범위와 저장
  - 시간이 끝났을 때 알림: 소리(Web Audio로 짧은 비프, 파일 없음) / 브라우저 알림(Notification, 권한 필요) / 화면 표시만
  - 다음 단계 자동 시작 여부
  - 새로고침·탭 닫힘 후 진행 중인 타이머를 이어갈지

## 지켜야 할 조건 (CLAUDE.md에서)
- HTML, CSS, JavaScript(ES 모듈)만. 외부 라이브러리·CDN·웹폰트·소리 파일 없음.
- `apps/pomodoro/` 안에서 자체 완결. 블로그·다른 파일을 import하지 않고 필요한 코드와 값은 **복사**.
- 블로그 색 팔레트를 따른다: `css/variables.css`의 변수 이름·값을 앱의 `:root`/`[data-theme="dark"]`에 복사. 집중/휴식 구분색 같은 앱 전용 색은 라이트·다크 양쪽에 변수로 정의하고, 글자/배경 대비 WCAG AA(4.5:1) 이상.
- 다크 모드: `<head>` 인라인 스크립트(블로그와 동일), `localStorage`의 `theme` 키 공유, 화면에 테마 토글(`aria-label`, ☀️/🌙), "← 블로그로" 링크(`../../`).
- 모바일: 375px에서 가로 스크롤 없음, 좌우 여백 16px 이상, 탭 대상 44×44px.
- 저장 키는 `pomodoro:{용도}`. 모든 `localStorage` 접근 `try/catch`, 불러온 값은 형식·범위를 검증한 뒤 사용.
- **시간 정확도**: `setInterval` 횟수를 세지 말고, 시작 시각·종료 예정 시각(타임스탬프) 기준으로 남은 시간을 계산한다(백그라운드 탭에서 타이머가 느려져도 맞도록).
- 타이머 로직은 DOM·`localStorage`·실제 시계를 직접 참조하지 않는 **순수 모듈**(현재 시각을 인자로 받아 Node로 테스트 가능).
- GitHub Pages 하위 경로(`/my-blog/`) → 모든 경로는 상대 경로.
- 접근성: 남은 시간을 스크린 리더가 매초 읽지 않게 하고(단계가 바뀔 때만 알림), 탭 제목에 남은 시간 표시(예: `24:13 집중 - 뽀모도로`).

## spec.md에 담을 내용
한국어로, 구현자가 추측할 필요 없을 만큼 구체적으로.
1. 개요
2. 기능 목록 — 단계(집중/휴식) 흐름, 버튼과 단축키, 오늘 완료 횟수, 알림, 다크 모드, 저장·불러오기, 사용법 안내 문구(위치와 실제 문장), 접근성
3. 파일 구조 — 순수 로직 모듈과 화면/입력 처리 분리 (예: `timer.js`, `main.js`, `theme.js`, `index.html`, `style.css`, `preview.svg`)
4. 핵심 로직 설계 — 상태 모양, 함수 이름·인자·반환값(현재 시각 주입), 저장 형식(키별 JSON 모양과 검증 규칙), 날짜 바뀜 처리
5. 화면 구성 — 마크업 골격(BEM 클래스), 375/768/1280px 레이아웃(큰 시간 표시, 진행 링 또는 막대)
6. 디자인 — 복사할 블로그 변수, 앱 전용 변수(라이트/다크)
7. 블로그 임베드 계획 — 카드 제목, 한 줄 설명, `preview.svg` 사양과 alt
8. 검증 체크리스트 — Review 단계용. 수치로 확인할 수 있게(예: 시작 후 `now+60_000`이면 남은 시간 24:00)
9. 범위 밖
10. 열린 질문 — 사용자가 정할 것만, 각 질문에 **권장 기본안**

맨 위에 `> 상태: 사용자 승인 대기. 승인 전에는 Build를 시작하지 않는다.`를 적는다.
