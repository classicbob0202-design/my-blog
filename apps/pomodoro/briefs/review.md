## Build 담당이 남긴 메모 (참고, 직접 판단할 것)
- Node 로직 테스트 20개 통과 보고. 실제 비프 소리, 알림 권한 창, 다른 탭 백그라운드 테스트, 대비율 직접 계산은 미확인.
- spec과 다르게 한 점: `applySettings`에서 휴식 단계의 `cycleCount`를 새 `longEvery`로 맞춤 / 자리를 비운 사이 완료는 완료 날짜가 오늘일 때만 기록.
- **판단 필요**: 진행 중·일시정지 상태에서 현재 단계 길이를 남은 시간보다 짧게 저장한 뒤 새로고침하면 `parseSession` 범위 검사에 걸려 세션이 버려진다(타이머가 처음부터). 사용자 입장에서 버그로 보이면, spec의 "진행 중 바꾸면 다음 단계부터 적용" 의도를 지키는 쪽으로 고쳐라(예: 진행 중 단계의 원래 길이를 세션에 함께 저장해 검증). 고쳤으면 Node 테스트를 추가해 확인하고 review.md에 이유를 적어라.
- 알림 영역(aria-live) 문구가 뒤쪽 탭에서 늦게 들어갔다고 함 — 앞에 보이는 탭(`tabs_select`)에서 확인 필요.

## 검사할 것
1. spec 8장 검증 체크리스트 항목 전부(통과/수정함/실패/확인 불가). 로직은 Node로 직접 다시 돌린다(시각은 숫자로 주입).
2. 브라우저 `http://localhost:8000/apps/pomodoro/` — 콘솔 오류, 375·768·1280px 레이아웃과 가로 스크롤, 라이트/다크, 탭 대상 44px, 키보드 단축키, 사용법 안내 문구, "← 블로그로" 링크, 탭 제목의 남은 시간
3. 코드: 금지 패턴(`innerHTML`, `!important`, `/`로 시작하는 경로, `:root`/`[data-theme="dark"]` 밖의 색 리터럴, 전역 변수, try/catch 없는 localStorage), `timer.js`에 DOM·저장소·`Date.now()`·인자 없는 `new Date()` 없음, 블로그 색 변수 사용
4. 저장값: 깨진 값·범위 밖 값·날짜 바뀜·localStorage 예외에서도 앱이 열리는지
5. 글자/배경 대비 WCAG AA(4.5:1)를 라이트·다크 모두 직접 계산(단계별 색 포함)
6. spec과 다르게 구현된 점이 합리적인지

## 고치는 기준
- 버그, 규칙 위반, spec 불일치는 고친다. 고친 뒤 같은 항목을 다시 확인한다.
- 큰 설계 변경이나 spec 자체의 문제는 고치지 말고 review.md에 "사용자 결정 필요"로 적는다.

## review.md 형식 (한국어)
- 요약(한 단락): 전체 판정
- 검사 결과 표: 항목 / 결과(통과·수정함·실패·확인 불가) / 메모
- 수정한 것: 파일, 무엇을, 왜
- 남은 문제와 사용자 결정 필요 사항
- 확인하지 못한 것(실제 소리, 알림 권한, 스크린 리더 등)

- 브라우저는 **`tabs_create`로 만든 새 탭의 tabId로만** 작업하고, 다른 탭을 닫거나 조작하지 않는다. 끝나면 그 탭을 닫는다. 서버(8000)는 끄지 않는다. 바뀐 파일이 안 보이면 `fetch(url, {cache: 'reload'})`로 갱신 후 새로고침한다.
