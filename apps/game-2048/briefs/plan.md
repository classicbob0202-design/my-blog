- 사이트는 GitHub Pages의 하위 경로(`/my-blog/`)에서 서비스된다. 모든 경로는 상대 경로로 쓴다.
- 나중에 블로그 메인(`index.html`)에 카드(제목, 설명, 미리보기 이미지 또는 iframe)로 들어간다는 점을 고려한다.

## spec.md에 담을 내용
한국어로, 간결하지만 구현자가 추측할 필요 없을 만큼 구체적으로 쓴다.

1. **개요** — 무엇을 만드는지 한두 문장
2. **기능 목록** — 반드시 포함:
   - 게임 규칙: 이동·합치기 규칙(한 번 이동에서 각 타일은 한 번만 합쳐짐, 예: `[2,2,2,2]` → `[4,4,0,0]`, `[2,2,4,0]` → `[4,4,0,0]`), 이동이 실제로 일어났을 때만 새 타일 생성(2: 90%, 4: 10%), 시작 시 타일 2개
   - 점수판: 현재 점수(합쳐진 타일 값만큼 더함) + 최고 점수(`localStorage`, 접근은 try/catch)
   - 승리(2048 도달 시 알림 + "계속하기") / 패배(이동 불가) 판정과 표시
   - 새 게임 버튼
   - 조작: 방향키, WASD, 터치 스와이프
   - 타일 이동·생성·합치기 애니메이션(가볍게, `prefers-reduced-motion` 존중)
   - 다크 모드: 블로그와 같은 `theme` 키를 읽어 따라가기(없으면 OS 설정)
   - 접근성: 점수 변화·게임 종료를 스크린리더에 알림(`aria-live`), 버튼 44px 이상
3. **파일 구조** — `apps/game-2048/` 아래 파일과 각 역할. 게임 로직(순수 함수, DOM 무관)과 화면 렌더링/입력 처리를 분리한다. `briefs/`, `spec.md`, `review.md`도 목록에 포함한다.
4. **핵심 로직 설계** — 판 데이터 구조, 주요 함수 시그니처(예: `move(board, direction) → { board, scoreGained, moved }`), 승리/패배 판정 방법, 난수 주입(테스트 가능하게)
5. **화면 구성** — 헤더(제목·점수·최고 점수·새 게임), 게임판, 조작 안내 문구, 종료 오버레이, 블로그로 돌아가는 링크. 모바일/데스크톱 레이아웃.
6. **디자인** — 색상 변수(라이트/다크), 타일 값별 색 규칙, 폰트(블로그 폰트 스택 재사용)
7. **블로그 임베드 계획** — 카드에 넣을 제목·한 줄 설명, 미리보기 이미지와 iframe 중 무엇이 적합한지와 이유, 메인 페이지 어디에 웹앱 섹션을 둘지 제안
8. **검증 체크리스트** — Review 단계에서 확인할 항목(규칙 엣지 케이스 포함)
9. **범위 밖** — 이번에 만들지 않는 것(예: 되돌리기, 판 크기 변경, 온라인 랭킹)
