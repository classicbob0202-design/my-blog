## 사용자 요구사항
- 2048 게임 (4×4, 방향키·WASD·스와이프)
- **점수판**: 현재 점수와 최고 점수. 그리고 **기록판**(지난 게임 점수 상위 기록 목록)을 권장안으로 제안하라 — 몇 개를 보관할지, 무엇을 함께 보여 줄지(점수, 최고 타일, 날짜 등), 언제 기록하는지(게임 오버, 새 게임 시작 시 진행 중 판 처리), 초기화 버튼 여부. 확정이 필요한 부분은 "열린 질문"으로.
- 진행 중인 판은 저장해서 새로고침 후에도 이어 하기.
- 사용법 안내 문구를 화면에 넣기(조작법, 저장 방식).

## 지켜야 할 조건 (CLAUDE.md에서)
- HTML, CSS, JavaScript(ES 모듈)만. 외부 라이브러리·CDN·웹폰트 없음.
- `apps/game-2048/` 안에서 자체 완결. 블로그·다른 파일을 import하지 않고 필요한 코드와 값은 **복사**.
- 블로그 색 팔레트를 따른다: `css/variables.css`의 변수 이름·값을 앱의 `:root`/`[data-theme="dark"]`에 복사. 타일 색처럼 앱 전용 색은 라이트·다크 양쪽에 변수로 정의하고, 글자/배경 대비 WCAG AA(4.5:1) 이상.
- 다크 모드: `<head>` 인라인 스크립트(블로그와 동일), `localStorage`의 `theme` 키 공유, 화면에 테마 토글(`aria-label`, ☀️/🌙), "← 블로그로" 링크(`../../`).
- 모바일: 375px에서 가로 스크롤 없음, 좌우 여백 16px 이상, 탭 대상 44×44px, 스와이프 중 페이지 스크롤 방지.
- 저장 키는 `game-2048:{용도}`. 모든 `localStorage` 접근 `try/catch`, 불러온 값은 형식·범위를 검증한 뒤 사용(깨진 값이면 새 게임).
- 게임 로직은 DOM·`localStorage`를 참조하지 않는 **순수 모듈**(Node로 테스트 가능, 난수는 인자로 주입).
- GitHub Pages 하위 경로(`/my-blog/`) → 모든 경로는 상대 경로.
- 스크린 리더: 게임판 상태를 원할 때 읽을 수 있는 대체 텍스트, 점수 변화는 과하지 않게 알림.

## spec.md에 담을 내용
한국어로, 구현자가 추측할 필요 없을 만큼 구체적으로.
1. 개요
2. 기능 목록 — 게임 규칙(합치기 예시 표 포함), 점수판·기록판, 승리/패배, 새 게임, 조작(키보드·스와이프), 애니메이션(reduced-motion 대응), 다크 모드, 저장·불러오기, 사용법 안내 문구(위치와 실제 문장), 접근성
3. 파일 구조 — 순수 로직 모듈과 화면/입력 처리 분리 (예: `game.js`, `scores.js`, `main.js`, `theme.js`, `index.html`, `style.css`, `preview.svg`)
4. 핵심 로직 설계 — 데이터 구조, 함수 이름·인자·반환값, 상태, 저장 형식(키별 JSON 모양과 검증 규칙)
5. 화면 구성 — 마크업 골격(BEM 클래스), 375/768/1280px 레이아웃
6. 디자인 — 복사할 블로그 변수, 앱 전용 변수(타일 색, 라이트/다크)
7. 블로그 임베드 계획 — 카드 제목, 한 줄 설명, `preview.svg` 사양과 alt
8. 검증 체크리스트 — Review 단계용. 수치·입력값으로 확인할 수 있게(예: `[2,2,2,2]` 왼쪽 → `[4,4,0,0]`, +8)
9. 범위 밖
10. 열린 질문 — 사용자가 정할 것만, 각 질문에 **권장 기본안**

맨 위에 `> 상태: 사용자 승인 대기. 승인 전에는 Build를 시작하지 않는다.`를 적는다.
