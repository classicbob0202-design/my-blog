## 1. 요약

**결과: 통과** (작은 문제 2건을 직접 고치고 다시 확인함. 환경 제약으로 브라우저에서 직접 확인하지 못한 항목 3개는 코드로 확인함 → 5장)

- 확인 환경: Claude 데스크톱 앱 내장 브라우저(Chromium), `python -m http.server 8000`, `http://localhost:8000/apps/game-2048/`
- 뷰포트: 375×812(모바일 프리셋), 1280×900, 데스크톱 기본
- 테마: `localStorage.theme`을 `light`/`dark`로 두고 새로고침, 저장값이 없을 때 `prefers-color-scheme` 에뮬레이션(light/dark)
- 방법: 콘솔에서 `import('./game.js')`로 로직 직접 호출, `KeyboardEvent`/`PointerEvent` 디스패치, `game-2048:state`에 판을 넣고 새로고침, 같은 출처 iframe으로 저장소 차단·잘못된 저장값·다른 탭 테마 변경 재현, 계산 스타일로 색·대비·크기 측정
- 브라우저 창이 숨겨진 상태라 `requestAnimationFrame`과 focus 이벤트가 돌지 않았다. aria-live 문구는 테스트 중에만 `requestAnimationFrame`을 `setTimeout`으로 바꿔서 확인했다(코드는 바꾸지 않음).

## 3. Build의 변경점 판단

1. **테마 스크립트를 `<meta charset>` 바로 뒤에 둠** — 타당함. 인코딩 선언은 문서 앞쪽 1024바이트 안에 있어야 하므로 charset을 맨 앞에 두는 것이 맞고, stylesheet보다 앞이라 깜빡임 방지 목적도 그대로 지켜짐. 블로그(viewport·title 뒤)보다도 앞에 있음.
2. **래퍼 max-width `calc(448px + gutter*2)`** — 타당함. spec대로 `480px` 고정에 768px 이상 여백 24px를 주면 판이 432px로 줄어 "최대 448px"과 어긋남. 1280px에서 판 448px, 375px에서 343px 확인.
3. **생성·합치기 효과에 CSS `scale` 속성** — 타당함. 위치를 `transform: translate`로 잡고 있어서 keyframes에서 `transform`을 쓰면 위치가 덮여 타일이 (0,0)으로 튐. 개별 `scale`은 따로 합성되고 레이아웃도 건드리지 않아 "transform/opacity만" 원칙의 취지에 맞음(Chrome 104+, Safari 14.1+, Firefox 72+).
4. **나머지 작은 변경** — 모두 타당함.
   - 버튼 hover 변수: 색을 변수로 관리하는 규칙에 맞음. 다크 hover `#9ccfff`/`#0f1215`도 대비 충분.
   - `.button-secondary`: 승리 오버레이에서 두 버튼을 구분해 줌.
   - preview.svg 2 타일 테두리: 흰 타일이 빈 칸과 구분되게 하는 spec 6.3의 그림자를 정적 SVG로 옮긴 것.
   - reduced-motion에서 `+N` 숨김: 동작 줄이기 취지에 맞음. 점수는 그대로 표시되고 알림도 됨.
   - 첫 방문 "새 게임" 알림 생략: 페이지를 열자마자 읽히는 불필요한 소리를 줄임. 버튼으로 시작한 새 게임은 알림.

## 4. 발견한 문제와 수정 내역

### 4.1 한글 입력 상태에서 WASD가 동작하지 않음 (수정)
- **문제**: 한국어 사용자는 한/영 키가 한글 상태인 경우가 많다. 이때 `keydown`의 `event.key`가 `'Process'`나 `'ㅈ'`/`'ㅁ'`/`'ㄴ'`/`'ㅇ'`로 와서 `KEY_DIRECTIONS`에 걸리지 않는다. 수정 전 `{key:'ㅁ', code:'KeyA'}` 등 4회를 보냈을 때 판이 그대로였다.
- **고친 곳**: `main.js` — `CODE_DIRECTIONS`(`KeyW/KeyA/KeyS/KeyD`)를 추가하고, `KEY_DIRECTIONS[key]`가 없을 때만 `event.code`로 방향을 찾게 함. Ctrl/Meta/Alt 무시, 방향키 `preventDefault`는 그대로 둠.
- **재확인**: `Process+KeyW`, `ㅁ/ㄴ/ㅇ`, `Process+KeyA`, 방향키 모두 기대한 대로 이동. `Ctrl+KeyD`, `x`, `ㅌ(KeyX)`는 무시됨.

### 4.2 점수 `<output>`이 암묵적 live region이라 두 번 읽힐 수 있음 (수정)
- **문제**: `<output>`은 암묵적으로 `role="status"`(= `aria-live="polite"`)라서, 점수가 바뀔 때마다 스크린리더가 점수 상자 값과 `#announcer`의 "점수 N점"을 겹쳐 읽을 수 있다(spec 2.8은 알림 영역을 하나만 두기로 함).
- **고친 곳**: `index.html` — `#score`, `#best` `<output>`에 `aria-live="off"`를 추가함. 시맨틱 요소와 라벨 연결(`aria-labelledby`)은 그대로.
- **재확인**: 속성이 적용됐고, 알림은 `#announcer` 하나로만 나감. 화면 표시는 변화 없음.

## 5. 미해결 / 확인하지 못한 것

- **확인하지 못함(환경 제약)**: 실행 중 OS 테마 변경 따라가기, `prefers-reduced-motion` 실제 동작, 오버레이 밖으로 나간 포커스를 되돌리는 `focusin` 처리. 브라우저 창이 숨겨져 있어서 `matchMedia` change 이벤트, rAF, focus 이벤트가 돌지 않았다. 모두 코드로는 맞게 되어 있다. 실제 기기에서 한 번 확인하기를 권한다(DevTools > Rendering에서 `prefers-color-scheme`·`prefers-reduced-motion` 전환).
- **실제 터치 제스처**: 스와이프는 합성 `PointerEvent`로만 확인했다. 실제 휴대폰에서 판 위 스크롤·핀치 확대 차단과 판 밖 스크롤은 직접 해 보지 못했다(`touch-action` 값은 확인함).
- **스크린리더 실제 낭독**: NVDA/VoiceOver로 듣지는 않았고, DOM 문구만 확인했다.
