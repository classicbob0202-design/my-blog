# 2048 게임 — Review 결과

- 작성: Review 단계 / 2026-10-30
- 기준: `spec.md`(8장 체크리스트, 10장 권장안), `CLAUDE.md`
- 방법: Build 보고를 쓰지 않고 직접 확인. Node(v24)로 `game.js`·`scores.js`를 import해 74개 항목 확인, 내장 브라우저(`http://localhost:8000/apps/game-2048/`, 새로 만든 탭 하나)에서 저장값을 주입해 흐름 확인, 코드 grep, 대비는 Node로 계산.

## 요약

**통과 (수정 없음).** 게임 규칙, 기록판, 저장/불러오기, 승리·패배(같은 이동에서 둘 다 성립하는 경우 포함), 키보드·스와이프 입력, 레이아웃(375·768·1280px, 라이트·다크), 접근성 처리 모두 spec대로 동작했다. 금지 패턴은 없고, 타일 숫자를 포함한 모든 글자 대비가 라이트·다크 모두 4.5:1 이상이다. 고칠 만한 버그나 규칙 위반을 찾지 못해 구현 파일은 바꾸지 않았다. 실기기 터치, 실제 화면 낭독기, `prefers-reduced-motion`의 CSS 쪽은 직접 확인하지 못했다(아래 "확인하지 못한 것").

## 남은 문제와 사용자 결정 필요 사항

- (낮음, 결정 필요 없음) 라이트 모드 메시지 보조 문구 대비가 최저 4.52:1로 기준에 겨우 걸친다. 덮개 불투명도(`--game-overlay` 0.88)를 올리면 여유가 생기지만 spec 6.2 값이라 그대로 두었다. 바꾸려면 spec 수정 후 반영.
- (참고) 메시지가 떠 있을 때 방향키는 게임에 쓰이지 않으므로 페이지가 스크롤될 수 있다. spec("무시한다")대로이며 문제로 보지 않는다.
- (참고) 진행 중 새 게임으로 남은 "중단" 기록은 새 게임 시작과 동시에 강조가 지워져 강조 표시가 보이지 않는다. spec 2.5 순서(기록 → 강조 해제) 그대로다.

## 확인하지 못한 것

- 실기기 터치 스와이프, 판 위 스크롤·확대 방지(합성 PointerEvent와 CSS 계산값으로만 확인)
- 실제 화면 낭독기로 듣기(알림 영역 글자, ARIA 속성만 확인)
- `prefers-reduced-motion` CSS 규칙의 실제 적용(브라우저 도구에 에뮬레이션이 없어 코드로만 확인, JS 쪽은 확인)
- 실제 다른 탭(블로그)에서 테마를 바꿨을 때의 동기화(다른 리뷰어 탭에 영향을 주지 않으려고 합성 `StorageEvent`로 확인)
- Ctrl+R 등 브라우저 단축키의 실제 동작(키 처리기가 가로채지 않는 것만 확인)
- `git status` 변경 범위(git 명령 금지)
